파일이동할 폴더

정리한 파일은 선택한 폴더 안에 분류 폴더를 만들어 옮겨요. 숨김 폴더(.으로 시작)와 node_modules는 건너뜁니다.

초안·시안·최종·찐최종·v2 같은 꼬리표를 떼고 같은 이름끼리 묶어요.

순서는 수정 시각 기준이에요(브라우저는 생성 시각을 알려주지 않아요). 부모는 앞선 파일 중 이름·내용(텍스트 파일)·크기가 가장 비슷한 파일이에요. 새 이름의 _from-v02는 직전 버전이 아니라 v02에서 갈라졌다는 뜻이에요. 웹페이지는 진짜 바로가기(.lnk)를 만들 수 없어서, 대신 경로가 담긴 _목록.txt를 만들어요.

크기·해상도가 달라도 같은 그림이면 묶어요(축소본, 재저장본). 가장 큰 해상도 파일을 남기는 쪽으로 기본 체크돼요. 회전·좌우반전·크게 잘린 이미지는 못 찾아요. jpg·png·webp·bmp·gif·avif만 지원해요.

기준을 고르면 삭제 후보를 보여줘요. 후보는 처음에 체크되어 있지 않으니 직접 고르세요.

브라우저는 ‘마지막 사용 시각’을 알려주지 않아서 수정 시각으로 판단해요. 읽기만 한 파일도 오래 안 쓴 걸로 나올 수 있어요. 버전 기준은 ‘비슷한 파일·버전’ 탭과 같은 방식으로 묶어요.

이동·이름 변경·삭제를 되돌릴 수 있어요. 기록은 선택한 폴더의 .정리기 폴더에 저장돼요.

파일·폴더 이름에 목적과 유효기간을 적어요. 권장 형식: 견적서__goal-발표용__exp20261231.pdf, 목적이 끝나면 맨 뒤에 __done. 예전 괄호형 {발표용✔}[~2026-12-31]도 계속 인식해요. 직접 이렇게 이름을 지어도 돼요.

현재 이름바꿀 이름

목적이나 유효기간 중 비워 둔 칸은 기존 값을 유지해요. 폴더 이름 바꾸기는 안의 파일을 새 폴더로 옮기는 방식이라 큰 폴더는 오래 걸려요(되돌리기 가능). 체크한 항목은 ‘정리 추천’의 규칙 6에 따라 만료·달성 시 삭제 후보에 올라요.

현재 이름문제바꿀 이름

날짜는 EXIF가 없으면 수정일을 써요. 판별이 애매한 형식(zip 계열, 옛 MS 문서)은 추정이라 미리보기에서 꼭 확인하세요. 웹페이지는 파일을 받은 사이트 주소를 알 수 없어요. 모두 되돌리기 가능해요.

깨진 파일 찾기

사진 위치정보(GPS) 찾기·제거

깨진 파일 검사는 파일 구조만 보는 간단한 검사라 일부 손상은 못 찾아요. GPS 제거는 위치 정보만 비우고 나머지 사진 정보는 남겨요. 제거 전 원본은 .정리기/원본백업 폴더에 보관해요.

폴더·파일 이름이나 선택 폴더 기준 경로가 패턴과 맞으면 스캔에서 빠져서 어떤 기능도 건드리지 않아요. 숨김 폴더(.으로 시작)와 node_modules는 항상 제외돼요. 이 브라우저에 저장돼요.

선택한 폴더 바로 아래의 폴더를 프로젝트로 보고 현황을 정리해요. 상태는 마지막 수정 기준이에요: 30일 이내 진행 중, 180일 이내 정체, 그 이후 보관 후보. 이름의 목적·유효기간 태그가 있으면 완료·만료가 우선해요.

프로젝트파일용량마지막 수정경과상태목적·유효기간

새 프로젝트 폴더 만들기

새 폴더에는 목적·유효기간을 적은 README.md가 같이 만들어져요(‘목적·유효기간’ 탭의 이름 형식을 따라가요). 폴더 생성은 되돌리기 기록에 남지 않아요. 완료 표시와 보관 이동은 안의 파일을 새 폴더로 옮기는 방식이라 큰 프로젝트는 오래 걸리고, 되돌리기로 복원돼요.

코드, 메모, 문서 초안 같은 텍스트 파일 두 개의 다른 줄을 보여줘요. 초록은 B에 추가, 빨강은 B에서 삭제된 줄이고, 왼쪽 번호는 A, 오른쪽 번호는 B의 줄 번호예요.

5MB 이하 텍스트 파일만 비교해요. ‘비슷한 파일·버전’ 탭의 ‘↔부모와 비교’를 누르면 그 버전과 부모 파일이 바로 비교돼요. 파일은 바뀌지 않아요.

코드·텍스트·마크다운 파일에서 TODO, FIXME, HACK, XXX와 “할 일:”, “수정 필요”가 들어 있는 줄을 모아요.
